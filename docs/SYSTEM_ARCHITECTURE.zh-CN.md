# AICore 系统架构

## 系统位置

AICore 是位于应用程序、操作系统与计算硬件之间的 AI 计算机控制层。

应用程序
    ↓
AICore
    ↓
操作系统
    ↓
CPU / GPU / NPU / 内存
    ↓
硬件

## AI 控制链

AICore 遵循以下控制流程：

观察 → 理解 → 预测 → 决策 → 校验 → 执行 → 测量 → 学习

控制循环从观察开始，持续把系统状态转换为经过校验的执行决策。

## 层级架构

AICore 提供三个相互独立的兼容层级：

L0 — 推理与工作负载理解
L1 — 任务契约与应用级集成
L2 — 原生操作系统级任务集成

L0、L1 和 L2 是相互独立的组件。

L0 不直接依赖 L1 或 L2。
L1 不直接依赖 L0 或 L2。
L2 不直接依赖 L0 或 L1。

每个层级都可以独立启用、禁用、删除或替换，且不需要修改其他层级的实现。

TierHub 和共享契约构成集成边界。

依赖方向如下：

             契约
                 ↑
        ┌────────┼────────┐
        │        │        │
       L0       L1       L2
        │        │        │
        └────────┼────────┘
                 ↓
              TierHub

## 控制安全

AI 不直接执行需要特权的系统操作。

AI 建议
      ↓
策略
      ↓
校验器
      ↓
执行器
      ↓
操作系统
      ↓
硬件

## 三层架构

AICore 由三个独立的兼容层级组成：

- L0 — 现实环境集成层
- L1 — 受控集成层
- L2 — 深度集成层

三个层级在架构上保持独立。它们通过稳定契约和集成边界通信，不直接耦合实现。
