# 系统需求

## 功能需求

| 编号 | 需求 |
|---|---|
| FR-01 | 采集 CPU、GPU、NPU、内存、电源、进程和应用等系统状态 |
| FR-02 | 将平台数据归一化为统一计算机状态 |
| FR-03 | 识别工作负载与交互上下文 |
| FR-04 | 生成并验证资源策略 |
| FR-05 | 通过适配器与运行时执行允许的资源策略 |
| FR-06 | 保存历史工作负载、策略、结果和用户画像 |
| FR-07 | 支持 L0/L1/L2 三种独立兼容路径 |
| FR-08 | 提供 IPC、命令行工具、终端仪表盘和网页仪表盘 |
| FR-09 | 支持插件发现、信任、生命周期和隔离 |
| FR-10 | 支持 AI 运行时、回退和模型生命周期 |

## 非功能需求

| 类别 | 要求 |
|---|---|
| 安全性 | AI 不能绕过校验器和执行器直接修改系统 |
| 隔离性 | 任一层级、插件和 AI 运行时均可单独禁用 |
| 可移植性 | Windows 与 Linux 共享核心层，平台差异归入适配器 |
| 性能 | AI 与仪表盘本身必须有可测量的开销预算 |
| 可观测性 | 决策、策略、执行和故障均可追踪 |
| 兼容性 | 现有软件可通过 L0 工作，不强制修改应用 |
| 可测试性 | 公开接口、适配器、流水线和故障路径均可测试 |
