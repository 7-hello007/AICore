# 插件安全

必须支持：

- 制品摘要
- Ed25519 签名
- 密钥标识与信任存储
- 显式权限
- 必要的进程隔离
- 资源预算校验（`memory_limit_mb > 0`）；当前子进程宿主**没有**强制执行操作系统级内存限制
- 超时控制
- 失败计数
- 禁用与回滚

本地开发绕过机制不得等同于生产信任。

操作系统级内存限制需要单独的平台隔离实现和验证；不得把 `PluginProcessSpec.memory_limit_mb` 的参数校验当作已经限制了插件进程内存。子进程 `stdout` 和 `stderr` 的单行读取上限为 64 KiB；`stdout` 超限会导致该插件终止并记录崩溃。

当前激活器拒绝未列入固定策略的插件、摘要或签名不匹配的制品、未列入固定策略的
权限，以及没有精确类型化绑定的控制权限。`process.priority_v1` 仅对
`Adapter` 清单、`process.control` 权限和操作员 `allow_control=true` 的
唯一活跃插件可绑定。插件确认消息只表示请求返回；平台进程适配器独立读回
优先级，读回失败进入现有验证与回滚流程。插件失败后不静默改用原生写入；
该插件没有亲和性写入能力。PID 0 在发送给插件前被拒绝，避免隐式选择插件自身或当前进程。GPU/NPU/电源插件控制仍未绑定。
`BuiltIn` 信任等级只能由
操作员固定策略赋予；清单不能自行提升信任等级。Linux 守护进程要求策略
文件由运行 UID 拥有，且不允许所属组或其他用户写入。`memory_limit_mb` 仍仅作参数校验，
不是操作系统级资源配额。模型模式不执行插件子进程。
