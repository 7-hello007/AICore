## Validation boundary for this task

The requested `simulated-platform` crate is verification infrastructure, not
a new destination product capability. It uses real read-only Linux/WSL and
Windows captures and exercises the existing Platform Mode interfaces in memory. Its
passing tests narrow integration risk for D-03/D-05/D-12 but do not close
hardware, effect or Windows native control acceptance gaps.

During the previous native-verification round, desktop authorization permitted certification with original-state capture,
restoration and readback, excludes installer execution, and confines downloads to
project `env/`. The current workspace suite has **no native-control filters**.
Owned child targets replace system/current-process targets; native power tests
capture the exact scheme GUID. Anonymous-principal pipe denial and owner access
are verified; a second interactive-login-user ACL test is **NOT VERIFIED**.
Native finite tick timings are measurements, not hard real-time certification.
Windows DXGI/SetupAPI identities do not supply GPU/NPU utilization on this
host. The AdaptiveLoop now declines model inference rather than substituting
zero for missing values on discovered devices. Direct queues work, but native
daemon route completion awaits real utilization or a validated feature contract.
A 60-second consent-gated read-only sample observed one foreground application
without window titles; it is not a representative personal-memory corpus.
GPU/NPU session placement does not claim power/clock tuning support. The WSL
checkout is not modified or synchronized. Current evidence and restoration
results are in the newest section of `DESTINATION_VERIFICATION_REPORT.md`;
older report sections remain historical.
