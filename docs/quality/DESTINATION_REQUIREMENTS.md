## Validation boundary for this task

The requested `simulated-platform` crate is verification infrastructure, not
a new destination product capability. It uses real read-only Linux/WSL and
Windows captures and exercises the existing Platform Mode interfaces in memory. Its
passing tests narrow integration risk for D-03/D-05/D-12 but do not close
hardware, effect or Windows native control acceptance gaps.

Current desktop code-layer authorization permits read-only native telemetry and capability tests, simulated Platform Mode, and use of the already-running local Ollama service; it excludes Windows native certification and installer execution. Any operation modifying host configuration (including platform process affinity/priority, device power or service state) requires a separate request before execution. Filtered workspace results must be reported as filtered. Same-user Windows pipe behavior has test evidence; cross-user ACL denial and hardware control remain separate acceptance evidence.
