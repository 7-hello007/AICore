## Validation boundary for this task

The requested `simulated-platform` crate is verification infrastructure, not
a new destination product capability. It uses real read-only Linux/WSL and
Windows captures and exercises the existing Platform Mode interfaces in memory. Its
passing tests narrow integration risk for D-03/D-05/D-12 but do not close
hardware, effect or Windows native control acceptance gaps.

Current desktop authorization permits native control/configuration operations with explicit restoration reporting, but prohibits installer execution and confines environment downloads to project `env/`. This continuation used a separate owned-child priority/readback/restoration probe and otherwise simulated Platform Mode, read-only identity/telemetry and local inference. The isolated suite retains five Windows native-control filters and must be reported as filtered. Same-user pipe, artifact/SID pin and v2 session behavior have test evidence; cross-user ACL, GPU/NPU/power, native hard deadlines and service behavior remain separate acceptance evidence. The WSL checkout is not modified or synchronized.
