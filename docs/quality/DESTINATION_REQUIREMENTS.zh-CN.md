## 本任务的验证边界

要求中的 `simulated-platform` 软件包是验证基础设施，不是新的目标产品能力。它使用真实只读采集的 Linux/WSL 和 Windows 样本，在内存中演练既有平台模式接口。通过的模拟测试降低了 D-03、D-05、D-12 的集成风险，但不能消除硬件、效果或 Windows 原生控制的验收缺口。

在上一轮原生验证期间，桌面授权允许在记录原始状态、恢复和读回的条件下认证，但禁止运行安装程序，并将下载限定于项目 `env/`。当时的工作区测试集**没有原生控制过滤器**。受控子进程代替了系统进程或当前进程目标；原生电源测试记录精确的方案标识。匿名主体的管道访问被拒绝，所有者访问通过；第二位实际登录用户的访问控制测试仍为 **NOT VERIFIED**。有限的原生控制周期耗时只是测量，不是硬实时认证。本机 Windows DXGI 与 SetupAPI 身份数据不包含 GPU/NPU 利用率。`AdaptiveLoop` 现在拒绝设备模型推理，而非用零替代缺失值。直接设备队列可运行，但原生守护进程的自动路由仍需要真实利用率或已验证的特征契约。经同意进行的 60 秒只读采样只观测一个前台应用，没有采集窗口标题，也不能构成代表性的个人记忆语料。GPU/NPU 会话放置不表示支持电源或时钟调节。WSL 副本未修改或同步。当前证据及恢复结果见 `DESTINATION_VERIFICATION_REPORT.md` 的最新章节；旧章节保留为历史记录。
