# V3.2 实现状态

## 范围

此源码树是 V3.2 工程收尾的实现候选版，目标是在不引入新产品版本边界的前提下，让现有架构内部一致并可运行。

## 已在源码中实现

- 统一的 `docs/` 架构文档包纳入源码树。
- 产品源码包不包含 `destination/`。
- 核心层、运行时和适配器之间继续通过接口划分边界。
- L0/L1/L2 仍是基于共享契约的平级适配器；任何层级都不依赖另一层级。
- 工作负载融合不再依赖过滤后列表的位置索引。
- `AdaptiveLoop` 通过 `TierHub` 能力接入工作负载、任务和适应提供者。
- 任务队列会移除过期项，并支持显式取消与清空。
- JSON/SQLite 记忆持久化修复了缓存与磁盘写入顺序问题；SQLite 记录时间戳采用明确的毫秒语义。
- 本地特征加权模型提供真实的文件支持推理路径；模拟 AI 不是生产默认值。
- AI 提供者与运行时路由共享同一个已加载的本地模型运行时实例。
- 插件子进程的标准错误输出持续被读取，避免管道背压死锁。
- 网页仪表盘默认只绑定本机回环地址，共享守护进程状态，提供自适应界面并发出事件流标识。
- 打包只使用一个工作区版本来源。
- 测试文件平铺在 `tests/` 下。

## 受平台限制的能力

GPU/NPU 控制仍以实际能力为门槛。不存在可诚实宣称在 Windows 和 Linux 上普遍受支持的安全跨厂商接口。不支持的硬件路径返回明确的 `NotSupported`，不能虚构成功。厂商专用插件和运行时是扩展点。

## 发布限制

当时的环境没有 Rust 工具链。因此，本历史文件不声称编译、静态检查、真实 Windows 服务安装、Linux 服务安装或真实硬件验证已通过。这些发布门槛需要持续集成或目标硬件提供证据。
